# Commercial Image-to-3D APIs and PeekaPlate's Tripo Integration

## Key Question 1: PeekaPlate's Existing Tripo Codebase Integration

### Takeaway
PeekaPlate already has a complete, hardened private single-image Tripo v3 pipeline (`tripo.py`, `generate_model.py`, `model_service.py`, and `serve_model_demo.py`) pinned to `v3.1-20260211` with `texture_alignment='original_image'`, `orientation='align_image'`, `enable_image_autofix=False`, and `publication={'eligible': False}`. Live Tripo generation has never executed because the signed-in Tripo account balance was `0` credits as of November 12, 2026, causing the pipeline's pre-upload `balance() == 0` guard to fail cleanly with `insufficient_credits`.

### Cited Findings
- **Pinned API host and endpoints:** [`tripo.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/tripo.py#L13-L123) hardcodes `API = 'https://openapi.tripo3d.ai/v3'`, disables HTTP redirects via `NoRedirect`, validates IDs with `r'[A-Za-z0-9_-]{1,160}'`, and calls `GET /v3/account/balance` (`balance`), multipart `POST /v3/files` (`upload` with `filename="cutout.png"`, `Content-Type: image/png`), `POST /v3/generation/image-to-model` (`submit` sending `{'input': identifier(file_token), **options}`), `GET /v3/tasks/{task_id}` (`task`), and `GET` on `https://cdn.tripo3d.ai` without an `Authorization` header (`download`).
- **Pinned model and generation parameters:** [`generate_model.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/generate_model.py#L22-L25) and [`tripo.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/tripo.py#L14) pin `MODEL = 'v3.1-20260211'` and `OPTIONS = {'model': MODEL, 'texture': True, 'pbr': True, 'texture_quality': 'standard', 'texture_version': 'v3.0-20250812', 'face_limit': 50_000, 'enable_image_autofix': False, 'texture_alignment': 'original_image', 'orientation': 'align_image', 'auto_size': False}` — [Tripo Cutout-to-3D Doc](file:///home/yacine105/t3-code-handoff/peekaplate/docs/tripo-cutout-to-3d.md#L112-L115).
- **Input and provenance validation boundaries:** [`generate_model.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/generate_model.py#L19-L203) enforces `MAX_IMAGE_BYTES = 10_000_000`, `MAX_JSON_BYTES = 1_000_000`, non-symlink regular local files, a PR25 `review-preview-v1` manifest with `review.status == 'needs_review'` and `publication.eligible is False`, UUID `dish_id`/`revision_id`, exact SHA-256 and byte-length matches on `cutout.png` (or `presentation.png`) and `fallback.jpg`, and `validate_png` requiring PNG `RGBA` dimensions in `256–2048` px with actual transparency (`alpha` min `0`, max `> 0`).
- **Output GLB and state-machine boundaries:** [`tripo.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/tripo.py#L15-L45) caps downloads at `MAX_GLB_BYTES = 50_000_000` and maps documented provider rejection codes (`REJECTIONS`, including `2010: 'insufficient_credits'`) only when no `task_id` is returned; [`generate_model.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/generate_model.py#L73-L269) enforces a `.run.lock` `fcntl.flock` lock, writes `status: 'submitting'` atomically before calling `submit()`, halts without auto-retry on `'submission_unknown'`, verifies returned `task_id` and `type == 'image_to_model'`, preserves `task_id` on download failure, and runs `validate_glb` (glTF 2.0 header/length, exactly 2 JSON+BIN chunks, JSON `<= 5_000_000` B, single buffer, bounds-checked `VEC3`/float `POSITION` accessors, and recursive rejection of any `'uri'` or `'url'` keys).
- **Private HTTP wrapper and DEV diner bridge:** [`model_service.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/model_service.py#L28-L238) wraps the pipeline in a single-tenant FastAPI service (`POST /v1/model-jobs`, `GET /v1/model-jobs/{job_id}`, `POST /v1/model-jobs/{job_id}/resume`, `GET /v1/model-jobs/{job_id}/artifacts/{filename}`) using a `>= 48`-char `TRIPO_SERVICE_TOKEN`, `BoundedSemaphore(2)`, `8192`-byte JSON cap, and `Cache-Control: no-store`, while [`serve_model_demo.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/serve_model_demo.py#L49-L64) strips `TRIPO_API_KEY` from the Vite diner environment and keeps all jobs `publication_eligible: False`.
- **Why live generation has not run yet:** On November 12, 2026, the signed-in Tripo console showed `0` tasks in the current month, `0` credits spent, `0` available credits, and `0` frozen credits; all verification (`62` focused unit tests, `61` HTTP API tests, and `5` browser regressions) used fake/mocked Tripo transports and synthetic triangle GLBs — [Tripo Cutout-to-3D Doc](file:///home/yacine105/t3-code-handoff/peekaplate/docs/tripo-cutout-to-3d.md#L152-L218). Pre-upload `client.balance() == 0` triggers `TripoRejected(2010)` (`insufficient_credits`) without uploading or submitting — [`generate_model.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/generate_model.py#L218-L227).
- **What `03_kimchi` is and how Tripo's alignment parameters affect it:** In PeekaPlate's 4-dish benchmark, `03_kimchi` is a `2000×1125` high-angle / 90° top-down dish photo (`32.66%` food foreground + `11.25%` plate = `43.91%` total foreground) featuring serrated kimchi cabbage margins, red chili-paste vs. green-leaf contrast, and a scalloped chili cup — [`dish-3d-delivery.md`](file:///home/yacine105/t3-code-handoff/peekaplate/docs/research/dish-3d-delivery.md#L144-L277). Tripo's `texture_alignment='original_image'` (the default) prioritizes matching the exact RGB colors, tones, and patterns from the source image rather than altering colors to match predicted geometry shading (`'geometry'`), while `orientation='align_image'` rotates the resulting mesh to match the input viewpoint — [Tripo API Docs](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQFr6o3hhsm-xhNVemaq3Lt17z_fs7Te_YD_RmUaZYtpNoi_O1KxRQu2X67-MOoKKUUi8Ecn99XAW_Zrbph8VHwyuBZs3cusSV-qMfNVdnE4UBJTS4hQJAKzzIns8lOJfrI8DMew_A==), [Tripo Orientation Spec](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQF9vwR0IszDiXax2gAqXBNDICh2V2HLRlQsz5HHizHGT2SVQkkvI3ENtxi4uXJ4UYGAeMwLUbzsMqozAunyrTaxReMN85lOAoYhKXOxaYEmEPJU5t6uiShEqlrBfkpfwyuxroHQLo1ZOLzudry0).

### Inferences
- Combining `texture_alignment='original_image'`, `enable_image_autofix=False`, and `orientation='align_image'` is specifically protective for dishes like `03_kimchi`: it preserves the exact photographic colors of chili paste, cabbage leaves, and ceramic surface from the hero camera angle without pre-generation tone remapping (`autofix=False`) or color smoothing (`geometry`), while orienting the GLB so the initial camera angle matches the captured dish photo.
- However, `texture_alignment='original_image'` only constrains fidelity where the camera actually observed the food (`front`/top); on a single high-angle photo like `03_kimchi`, Tripo still synthesizes the back and underside geometry and textures, which remain unverified under ADR 0004.

### Gaps
- **Live Tripo GLB output on PeekaPlate cutouts:** Because the Tripo account had `0` available credits, no real Tripo GLB has been generated or visually inspected for `03_kimchi` or any PR25 cutout (`docs/tripo-cutout-to-3d.md`).
- **`submit()` payload key shape vs. latest Tripo v3 examples:** [`tripo.py`](file:///home/yacine105/t3-code-handoff/peekaplate/processing/src/peekaplate_processing/tripo.py#L110) sends `{'input': file_token, ...}`, whereas some web documentation snippets show `input` as an object (`{"type": "url", ...}`). Although `docs/tripo-cutout-to-3d.md` verified the wire format against Tripo docs on November 12, 2026, live execution against `/v3/generation/image-to-model` remains unconfirmed until credits are funded.

## Key Question 2: Tripo3D API (v2.5 / v3.0 / v3.1 & Ultra / Multi-view Features)

### Takeaway
Tripo3D's v3 API (`v3.1-20260211`) supports both single-image (`image-to-model`) and 2–4 view (`multiview-to-model`) PBR GLB generation at **$0.30/dish** for standard textured output (`$0.50/dish` with `geometry_quality='detailed'` Ultra mode), completing textured jobs in roughly **~120 seconds**. It offers fast throughput and solid organic rim silhouette preservation, though shallow plate interiors can flatten on single-image runs and raw texture crispness can trail Hyper3D Rodin Gen-2 or Meshy 4K/8K.

### Cited Findings
- **Endpoints and multi-view support:** Tripo v3 exposes `POST /v3/generation/image-to-model` (single image via `file_token`, URL, or `task_id`) and `POST /v3/generation/multiview-to-model`, which accepts **2 to 4 images** (`front` mandatory, plus optional `left`, `back`, `right` via view-key objects `[{"front": ...}, {"back": ...}]`, legacy 4-string positional arrays, or `task_id`) — [Tripo API Docs](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQFB6rVDhFOrdOqThuV3omtTq0ScOnI3XWvwhVwhp4hmoNQFfItI3MyjK09yY79AGLx8hmD_xG2jcXfV1OufaNrX74seU5wr8ZrDjtML55ouUCG9rJvefo2oLbQMj6B-QPEYYH1I_Lm2iw==), [Tripo Multiview Docs](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQGJBT68MRQtHBRSmIIuVWbWr7GlTwYvi1Qe6ZZpCFXhKOWpZpUR6fj-6GlP_zxtJLg-95kPKKzH5IclzaRbAlOfLS7t5ciFYjT1Io84OwWEB0KH40ekZ5POLkcCAPlzGKw7YCzphiB6axnTdqKFn1S8HUIQCvYt4DCYNSVGhvLtLq1h).

### Inferences
- PeekaPlate's current `OPTIONS` (`v3.1-20260211`, standard texture + PBR, no `detailed` geometry, no `quad`) corresponds to **$0.30/dish** (`30` credits), and switching to Tripo's `multiview-to-model` endpoint (2–4 captured views) appears to carry either the same **$0.30/dish** cost or slightly lower (`$0.20`), without extra per-view GPU engineering.
- Because `quad=true` returns FBX topology, PeekaPlate's GLB-only pipeline (`validate_glb` + `model-viewer` / Three.js `GLTFLoader`) is well served by keeping `quad` disabled and using `face_limit: 50_000` (or decimating further for mobile).

### Gaps
- **Exact `v3.1` vs. `v3.0` vs. `v2.5` differential pricing:** Official Tripo pricing tables retrieved list a single H-series/v3 schedule (`20/30/40/50` credits) and did not isolate whether `v2.5-20250123` is discounted vs. `v3.1-20260211`, nor whether `multiview-to-model` is `20` or `30` credits for standard textured `v3.1` given the conflicting summary figures.
- **Explicit `pbr=true` credit surcharge:** Retrieved Tripo tables bundled PBR under standard/detailed texture tiers (`30`/`40`/`50` credits) without stating whether toggling `pbr=false` reduces cost below `30` credits.

## Key Question 3: Hyper3D / Deemos Rodin (Gen-1.5 / Gen-2 API)

### Takeaway
Hyper3D Rodin Gen-2 / Gen-2.5 (`api.hyper3d.com/api/v2/rodin`, also hosted on Fal.ai, Replicate, and Runware at **$0.40/run** standard or **$1.20** HighPack) delivers benchmark-leading organic sculpting, texture delighting, multi-view conditioning (up to 5 views), and `bbox_condition` proportion bounds. Its main operational caveat for automated dish pipelines is higher generation variability and unseen-backside reroll rate compared to Meshy and Tripo, alongside a **$120/month** Business plan gate for direct Hyper3D API access.

### Inferences
- **Comparative matrix across platforms:**
  - **Tripo3D v3.1 (`v3.1-20260211`):** **$0.30/dish** (`$0.50` Ultra), ~`120s`, `2–4` multi-view, explicit `texture_alignment='original_image'`, zero GPU DevOps, already implemented locally in PeekaPlate (`tripo.py`/`generate_model.py`).
  - **Hyper3D Rodin Gen-2:** **$0.40/dish** via Fal/Replicate (`$1.20` HighPack) or `~$0.29` on `$120/mo` Business bundle, ~`120–180s`, up to `5` multi-view (`concat`) + `bbox_condition`, best peak organic detail and delighting, higher reroll tax.
  - **Meshy (`meshy-6` / `meshy-7.1`):** **$0.38–$0.70/dish** (`30–35` credits across Ultra/Pro plans), ~`20–60s`, `1–4` multi-view, webhooks, highest consistency/lowest rerolls, requires `$20–$100+/mo` plan.
  - **Tencent Hunyuan3D Cloud:** **~$0.47–$0.53/dish** single PBR (`~$0.61–$0.68` multiview PBR, `~$0.74–$0.83` with custom face count), `3` concurrent tasks default.
  - **Self-Hosted `TRELLIS.2-4B` (Beam / RunPod Flex):** **~$0.10–$0.37/dish** compute-only (excluding storage, egress, retry failures, and engineering time), single-image only, `>= 24 GB` VRAM, gated Meta DINOv3/BRIA/NVIDIA dependency licenses.
- **ADR 0004 alignment:** Single-image calls on *any* commercial API remain strictly `publication_eligible: false` private drafts (`needs_review`). Multi-view commercial APIs (`multiview-to-model`, Rodin `concat`, Meshy `multi-image-to-3d`, Hunyuan3D `MultiViewImages`) improve geometric constraint over single-photo `TRELLIS.2-4B`, but because generative multi-view models still synthesize occluded undersides without calibrated camera reprojection, publishing them to diners under ADR 0004 still requires either restricted orbit inspection against real held-out views or pairing/benchmarking against deterministic COLMAP photogrammetry, plus explicit decimation (`<=35k–50k` faces) to meet mobile T2 delivery budgets.

### Gaps
- **Side-by-side empirical plated-food benchmark across commercial APIs:** No live generation has been run on PeekaPlate's 4 benchmark dishes (`01_pizza`, `02_tteokbokki`, `03_kimchi`, `04_gimbap`) with Tripo `v3.1`, Rodin `Gen-2`, Meshy `7.1`, or Tencent `Hunyuan3D 3.0`, nor has `TRELLIS.2-4B` been run on an `sm_80+` GPU (`RTX 4090`/`A100`/`H100`) at `1536_cascade` with `remesh_project=0.0`.
- **Privacy, retention, and vendor DPA verification:** Sending private restaurant dish photos (`ADR 0005`) to third-party hosted 3D APIs (Tripo, Hyper3D, Meshy, Tencent Cloud) requires checking each vendor's API data-retention, training opt-out, and regional processing terms before processing real owner uploads outside synthetic/rights-cleared demos.
- **Exact `TRELLIS.2-4B` `1024³/1536³` wall-clock + cold-start cost on Beam / RunPod 4090:** Real RunPod Flex / Beam cold-start and `o_voxel.postprocess.to_glb` export durations for `TRELLIS.2-4B` on an `RTX 4090` or `A100` have not yet been measured in PeekaPlate's pilot (`docs/research/dish-3d-delivery.md`).
