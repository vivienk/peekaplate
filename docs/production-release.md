# Production release during the Meta freeze

Use a reviewed exact commit from the official repository's **develop** branch for a manual production release during the freeze. This is a proposed exception to the source-branch rule in [ADR 0012](adr/0012-main-environment-promotion.md). Keep its independent release sign-off and separate environment boundaries. Do not deploy to the existing Meta staging projects or update main. Inspect the exact candidate in an isolated environment before domain cutover.

5. Deploy the exact verified SHA, with explicit production project names and code hashes. ## Tracking and reporting boundary

The additive diner events keep `dish_activity_checkpoint` for elapsed time, use `dish_portion_opened` only when a portion renders, and retain `dish_compared` for displayed comparison evidence. A result can render the anchor and two other dishes. Pair rows share a comparison ID, so count distinct IDs to measure completed Compare actions. The canonical ingest route derives venue and publication from its signed menu token. It does not use a browser venue field or a PostHog project ID as tenant authority.

Standalone published menu pages on the production diner origin automatically send supported interactions to canonical ingestion and configured PostHog. The embedded Screen 13 phone preview sends no events. The production diner has no consent prompt. The browser’s Do Not Track and Global Privacy Control signals stop both destinations. Staging retains its existing opt-in. Diner activity uses randomly generated identifiers and does not include names, emails or account IDs. Verify the public privacy disclosure before activating the production build. Production captures may use the resolver’s public venue and publication IDs for internal filtering. Canonical ingestion checks the signed tenant and publication. A supplied dish/revision pair still needs to be checked against that publication’s verified manifest before owner metrics can use it. The owner reporting and AI data-source change needs a reviewed extension to [ADR 0013](adr/0013-posthog-export-boundary.md) and [ADR 0003](adr/0003-intent-evidence.md) before production activation.

For live and historical reporting, validate event identity, tenant, publication, occurrence time and cohort before exposing metrics.
